# 量化策略研究守门清单

> 每条坑都出过事，括号里是事故现场。用法：**写代码前扫 A/B，结果出来先做 C，下结论前过 D/E，碰外部平台/移植加 F，汇报按 G。**
> 唯一权威记录 = `notebook.md` 持久结论；本清单是操作层的提炼，数字细节以权威处为准。

## 0. 六条红线（.hermes.md 硬规则，违反 = 结果作废）

1. 回测起点 ≥2016 —— 2010-2015 源数据本身稀疏（2010 年仅 33 个交易日），不是脚本 bug。
2. 任何回测先检查"每笔能否买得起 1 手"并统计买不起天数 —— 小权益 × 高波动年会出现整段零交易，结果被样本选择污染（$25k×NQ 2026 年 0 交易）。
3. 突破判定用收盘价，不用 high/low 触及 —— 触及判断下 26% 交易日两边同时越界，if/elif 系统性多头偏差。
4. 大单被拆单（部分成交）时止损必须按**累计已成交数量**挂 —— 旧代码只给第一笔挂止损，剩余仓位裸奔到收盘，假左尾 min R -11.66，修复后 Sharpe 1.18→1.63。
5. 参数搜索报 walk-forward 样本外，不只报全样本最优；结论必须附样本量、区间、成本假设。
6. 成本/滑点假设不许为了好看调低；不为迎合而优化参数。

## A. 数据与时间语义（写代码前读）

1. **期货 session 归属**：ETH 日从 18:00 ET 起，`sess = (ts_ET + 6h).date()` 让 18:00 起的盘归属次日。（VWAP-MR 坑）
2. **禁止按 time-of-day 提前 break**：session 数组头部是前晚 18:00-23:59 的 bar，`if t >= end: break` 在第一根就跳出，整天作废。用窗口条件 `start <= t < end` 扫全数组。（VWAP-MR 第一版"胜率 99%"假象的一半）
3. **计数 ≠ 索引**：有效 bar（如 <15:55）不是数组前缀，"有效根数"不能当下标上界；用 `np.max(np.where(valid)) + 1`。（VWAP-MR 假象的另一半，两个 bug 一个 session 踩两遍）
4. **bar 标签 = 左标签（开盘时刻）**：区间右端写"下一段的开始"配 `<`（如 `[9:00, 9:30)`），**绝不配 `<=`**——把开盘首根吞进区间 = PF 1.04 灾难（中位区间宽 15.5→28pt，突破信号变噪声）。不要写 9:29 这种末分钟数（隐式依赖 5min 网格，换 1min 数据悄悄退化）。
5. **入场价 = bar 收盘价**：窗口 `9:30 <= t < 10:10` 实际最早入场墙钟是 9:35；EOD 平仓价 = 标签 15:55 的 close = 墙钟 16:00 价。实盘 adapter 时间戳必须同口径核对（live 用 `_ib_bar_to_ts_event` 对齐过）。
6. **每日 bar 根数断言**：3,627 天里 12 天盘前 5min bar 数 ≠ 6（COVID 熔断/半日假 Good Friday），过去一直静默用残缺区间算。**已实装（2026-09-17，v5.0）**：`FsmEnv.range_status` 返回 `ok`/`partial`/`missing`（预期根数 = `RANGE_BARS_EXPECTED`），只告警不改行为；live 侧另有与 bar 流解耦的 `range_check` 闹钟（9:31 ET）。新写数据管道时照此把「完整度」当一等公民——只判 `is not None` 抓不到残缺。
7. **半日市按当日实际最后一根 K 线收口**（`build_day_last_bar_map`），不要硬编码 15:55。硬编码日历（`HALF_DAYS`）必有遗漏（总统日彩蛋：原版裸奔到 18:00 夜盘）→ 日历之外必须有兜底（定时闹钟）。
8. 换数据粒度/换品种后，时间语义逐条重新核对，不能默认沿用（1min 下 `[9:00,9:30)` = 30 根，行为不同但写法相同）。

## B. 成交与成本建模（回测可信度的一半在这里）

1. **滑点口径决定参数结论**：滑点按 tick 固定、止损按 ATR 缩放 → 低波动年成本占 1R 比例爆炸（2017 年止损中位 3.67pt，2 tick 来回 ≈ 25-33% 的 1R，直接吃穿 edge）。**选参数必须用含滑点口径**；零滑点数字只在实测 ≤0.5 tick 时可用。
2. 紧止损对滑点极敏感（0.5% 档 1R≈0.25pt，2 tick 滑点 ≈ 8R）——这是紧止损档爆仓的机制之一。
3. 名义止损 < 1 tick 会被钳位到 1 tick，该档参数本身失真，结论作废。
4. **回测止损 = 触发价成交、无跳空穿越建模**：R 有硬底（-1.24），实盘新闻 K 线跳穿会更糟 → 一切实盘收益预期都是上界，真单滑点采集（slippage_tracker）出来之前不下"能赚多少"的结论。
5. **MNQ 不改善成本/R 比例**（tick 口径下与每点乘数无关，MNQ 1 tick ≈ NQ 2 tick 摩擦，已实测等价），只解决买得起 1 手的颗粒度。
6. **换品种参数必须单独重调**：ES 直接套 NQ 调好的参数 = 年化 -7.8%/MDD -71%（波动、点值、结构都不同）。
7. CFD/点差类成本先算量级再跑：NAS100 点差 1-2 点 ≈ 4-8 个 NQ tick，成本/R 是 MNQ 的 3-6 倍，不能期待复现期货侧收益。

## C. 结果一致性检查（跑完先做，再谈结论）

1. **"概率高得离谱"先查内部一致性**：胜率 99%、中位持仓 0 分钟这种输出，先怀疑代码再怀疑市场。（VWAP-MR 第一版）
2. **两条独立链路互证**：重大数字用不同实现复算（REPORT.md 附 2 vs 主线脚本逐格吻合才算坐实）。
3. **逐笔 diff 前先对齐参数态**：cBot 默认 5R/10:10 vs 磁盘 .py 实验态 7R/10:30——不对齐的 diff 全是废纸。**引用任何脚本数字前先看磁盘上的实际参数，别信文档默认值。**
4. 同 bar 双触按保守计（止损优先于目标）；入场按 1min 收盘对 tick 实际略乐观——方向性偏差要写明。
5. 确定性检查：同脚本重跑 3 次应逐位一致（引擎有隐藏随机性时先抓出来）。
6. 计数器断言（止损单数 = 信号数、BE 触发次数、EOD 笔数）作为干净数据的自动断言跑在每次实验里。

## D. 统计与验证纪律（下结论前）

1. **walk-forward 样本外是底线**：6 窗口 5训1测、6/6 段正 + 最差年数字，比全样本年化更值得报。θ* 随 regime 漂移本身就是信息（2021-23 选 5-7.5%、2024-26 选 10%）。
2. **引用数字必须带口径**：起点窗口（2019 起年化 75.4% vs 2016 起 56.9%——同一个策略）、滑点 tick、本金、合约。改起点剔掉亏损年 = 样本选择不是改进（2020 起 MDD -47.8%→-28.3% 全靠剔掉 2017）。
3. **右偏长尾策略降权 Sharpe**：Sharpe 1.63 vs Sortino 9.25（Sharpe 低估右偏）；看 Sortino/PF/胜率结构/R 分布分位。分布假设先检验（正态 Shapiro p~1e-71 被拒，对数正态最优）。
4. **利润集中度必查**：前 5 大赢单 = 总利润 47%、前 20 = 113% → 对系统在线率要求近 100%，漏一个大趋势日改变年度成绩。
5. **统计现象 ≠ 可兑现 edge**：首破 ≥1σ 后收盘前触回 VWAP ≈100% 是真的，但紧止损 54-66% 先被路径噪声打掉——"收盘前的统计属性"不等于"路径内拿得到的钱"。
6. **负结果如实记录并尊重**：trailing 负贡献、1R 保本砍长尾、10R 止盈负贡献、VWAP-MR 三轮（换窗口/换品种/加过滤）全负不开坑——否定结果和正结果同等价值，不许悄悄丢弃。
7. **截断右尾的工具默认伤策略**：本策略全部利润来自右尾大赢家（P95 +9.6R/P99 +16.2R，胜率仅 15-21%），任何止盈/紧保本/trailing 都要先过 A/B 验证再谈"优化"。
8. **区分"从没 edge"和"edge 衰减"**：|t| 对照失效监控框架（4.35 = 停机线量级）；t=-4.14 且从第一天起就负 = 从头就没有，不是衰减。
9. 参数报告多口径并排（Sharpe 驼峰在 7.5% 而 Calmar 最优在 5%——口径不同结论不同，报口径而不是只报对自己有利的那个）。
10. 复利终值会被路径放大：$190 万 = edge 715.6R × 复利 18×，且 45% 集中在 2026 一年。报固定手数口径做交叉参照。

## F. 外部平台/移植专项（cTrader、IB 等）

1. **API 语义逐个核实，不凭直觉**：cAlgo 的 `Bar` 是 struct（不能 = null）、`Bars` 没有 `Last(n)`、`ExecuteMarketOrder` 止损参数单位是 **pips 不是价格**；IB paper 端口 4002 / live 4001 / TWS 才是 7497（易混）。启动时打印自检（时区三对照、bar 节奏）用首日日志核对。
2. **CLI 参数键名用 metadata 输出核对**：属性名 ≠ 显示名（中文显示名），传错键静默用默认值。
3. **回测 CLI 的成本参数逐个查**：`--commission` 未传 `--commission-type`（注释口径 ≠ CLI 默认）、`--spread=0` 语义未核实——零点差回测对薄成本策略是误导。
4. **只在启动时算一次的数据会冻结**（cBot ATR 多日冻结：连跑第 2 天起止损停在启动前）；回调/下单返回值必须查（`ClosePosition` 返回值不查 → 泄漏标志吞掉真实止损成交统计）。
5. **二手数字不可信，规则先抓官方原文**：Lucid prop 规则按论坛/旧笔记建模，官方核对后 funded 数字缩水 60%。任何"别人的费率/规则/上限"动手建模前先到源头核对。
6. 延迟数据不能当实时下单依据（IB 2188：延迟 tick 能收但 15 分钟延迟对开盘策略致命）。
