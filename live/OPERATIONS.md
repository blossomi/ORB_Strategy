# ORB 实盘操作手册

> 适用范围：`live/` 文件夹（MNQ 5 分钟 ORB，参数 = 7.5%×14日ATR 止损 × 5R 拉保本 × 0.7% 风险）。
> 所有时间均为**美东时间 ET**。改代码前先读第 8 节「定期维护」。

---

## 1. 一页速查（每天就这三步）

```bash
# ① 盘前启动（8:30–8:50，插好电源、IB Gateway 已登录 paper）
cd /Users/blossomx/workspaces/Deepseek_Harness/live
mkdir -p logs
caffeinate -s nohup ../.venv/bin/python live_ib_demo.py > logs/nohup_$(date +%Y%m%d).log 2>&1 &
tail -f logs/nohup_$(date +%Y%m%d).log        # 盯到看见启动检查清单全过为止

# ② 收盘后停止（15:56 之后）
kill -INT $(pgrep -f live_ib_demo)            # 千万别 kill -9（会跳过日结汇总）

# ③ 当日核对（1 分钟）
grep -E "\[信号\]|\[BE\]|\[收盘\]|\[日结\]" logs/live_*.log | tail
```

## 2. 这套系统是什么

```
live/
├── live_ib_demo.py        主程序：连 IB Gateway → 订阅 MNQ 5min bar → ORB 信号 → 下单/拉保本/收盘平仓
├── slippage_tracker.py    滑点记录器（信号价 vs 成交价，落 live_slippage.csv）
├── _verify_live_logic.py  上线前回归验证（改完代码必跑，见第 8 节）
├── OPERATIONS.md          本手册
├── logs/                  ★ 所有运行记录，每次运行一个新文件，从不覆盖、从不清空
│   ├── live_YYYYMMDD_HHMMSS.log    策略事件流（bar/区间/突破/信号/成交/BE/日结）—— 对账看这个
│   └── nohup_YYYYMMDD.log          控制台全量（含 nautilus/adapter 报错，如 2188/断线）
└── live_slippage.csv      滑点明细（追加写；换阶段时归档，见 5.3）
```

程序单进程跑在本机，**机器睡着 = 断连 + 收盘平仓没人执行**。入场后挂的止损单存在
IB/Globex 服务器端，睡眠期间止损保护仍然有效；但「拉保本改单」「收盘平仓」「新信号」
都依赖本机进程活着——所以启动命令用 `caffeinate -s` 包住（进程活着 Mac 就不睡），且
笔记本必须插电源（`-s` 只在接电源时生效）、不合盖。

## 3. 一次性前提设置（只做一次）

1. **IB Gateway**：登录 paper 账户（会要 2FA），端口 **4002**，API 类型选 **IB API**（非 FIX/CTCI）。
   建议在 Gateway 设置里打开 auto-restart，免得 IB 每日维护重启后卡在确认弹窗。
   （正式实盘时换 live 账户 + 端口 **4001**，并同步改代码顶部 `IB_PORT`/`ACCOUNT_ID`。）
2. **CME 行情订阅**：Client Portal → Settings → Market Data Subscriptions → 订
   **US Futures Value Bundle**（L1，~$10/月，月佣金 ≥$30 免除）。paper 账户自动共享。
   订完后代码顶部 `MARKET_DATA_TYPE` 必须是 `REALTIME`（当前已是）。
3. **电源与睡眠**：启动命令已含 `caffeinate -s`；只需保证**插电源**。想双保险可在
   系统设置 → 电池/显示器 里勾「显示器关闭后防止自动进入睡眠」。

## 4. 每日盘前启动流程（8:30–8:50 ET）

1. 起 IB Gateway，登录 paper（2FA），等左下角连接状态正常。
2. （一次性订完后跳过）确认 Client Portal 里 CME 包状态 active。
3. 插电源。
4. 执行速查卡 ① 的启动命令。
5. **启动后 1 分钟检查清单**——在 `tail -f` 里依次确认：

| # | 应看到 | 含义 | 看不到说明什么 |
|---|--------|------|----------------|
| 1 | `[启动] TradingNode → IB Gateway 127.0.0.1:4002 (DUQ715008)` | 进程起来、日志落盘 | 命令/路径写错，看 nohup 文件 |
| 2 | `[启动] 模式: DRY_RUN ...` | 当前阶段正确 | 阶段搞错，回去改 `DRY_RUN` |
| 3 | 合约加载成功（无 error） | `MNQZ6.CME` 定义拿到 | Gateway 没就绪/端口不对 |
| 4 | 无 `2188` / error | 行情权限通 | 订阅没生效 → Gateway 重登一次 |
| 5 | `[ATR] 前一日 14日ATR = xx pt` | 日线请求成功，止损有依据 | 失败则当天不会交易（安全侧） |
| 6 | `—— 新交易日 YYYY-MM-DD ——` | bar 已开始流入 | 正常（首根 bar 要等 9:00/回填） |

9:30 之前没有 `[bar]` 行**不一定**是问题——`[bar]` 从 9:00 开始记。9:30 一过若出现
`区间为空 (没收到盘前 bar?)`，说明实时数据没通（延迟模式或订阅未生效），当天作废。

## 5. 盘中会发生什么（对照着看 tail -f）

一天的事件流长这样（真实回放，前缀是墙钟时间）：

```
09:00 [bar] 09:00 O=… H=… L=… C=… V=447 → 区间 8732.75~8734.75   ← 每根 bar 一行, 盘前段附区间
09:05 [bar] 09:05 … → 区间 8730.50~8734.75                        ← 区间随 bar 更新
09:30 [bar] 09:30 O=… C=8735.75 V=7514                            ← 9:30 起不再附区间
09:30 [突破] 09:30 C=8735.75 ↑ 破 上沿 1.00pt (区间 8730.00~8734.75)
09:30 [信号] BUY @ 8735.75 18 手 (… ATR 62.55 → 止损距离 4.75pt ≈ 每手风险 $10)
09:30 [入场成交] 8735.75 × 18 手 | 滑点 0.0 tick | 信号→成交 120 ms    ← DRY_RUN 无此行
09:30 [止损挂单] SELL 18 手 @ 8731.00 (入场 8735.75, R=4.75pt, 达 5R 拉保本)
09:35 [持仓] 浮盈 +2.21R / 峰值 2.74R (止损 8731.00, 5R 拉保本)      ← 持仓期每根 bar 一行
09:55 [持仓] 浮盈 +5.00R / 峰值 5.53R (止损 8731.00, 5R 拉保本)
09:55 [BE] 浮盈达 5R (峰值 5.53R) → 止损拉到保本 @ 8735.75 (原 8731.00), 之后持有到收盘
10:00 [持仓] 浮盈 +4.53R / 峰值 5.53R (止损 8735.75, 已拉保本)
…     （也可能 [止损成交] → 初始止损出场 / 保本出场）
15:55 [收盘] 平掉 18 手 @ 信号价 xxxx
15:55 [收盘成交] xxxx | 滑点 0.0 tick
```

**注意两类「正常」**：
- **全天没有 [信号]**：约 1/3 的日子区间不突破，不交易是策略的一部分。10:10 后就定了。
- **DRY_RUN 阶段**：只有 `[突破]`/`[信号]`，没有成交/止损/持仓行——没有下单就没有这些。

## 6. 如何看日志（收盘后核对）

### 6.1 两个文件的分工
- `logs/live_*.log`：**对账看这个**。策略全部关键动作 + 墙钟时间戳。
- `logs/nohup_*.log`：**报错看这个**。nautilus/adapter 的连接、订阅、2188、断线都在这。

### 6.2 grep 速查表
```bash
grep "\[bar\]"    logs/live_*.log          # 逐根 bar OHLCV（原始底稿）
grep "\[突破\]"    logs/live_*.log          # 突破时刻/方向/幅度
grep "\[信号\]"    logs/live_*.log          # 入场信号 + 手数 + 止损距离
grep "\[止损挂单\]" logs/live_*.log          # 止损价（对照信号里的 ATR 算一下）
grep "\[持仓\]"    logs/live_*.log          # 每根 bar 的浮盈 R / 峰值 R
grep "\[BE\]"     logs/live_*.log          # 何时拉保本（新旧止损价）
grep "\[止损成交\]" logs/live_*.log          # 止损/保本出场 + 滑点
grep "\[收盘\]"    logs/live_*.log          # 收盘平仓
grep "\[日结\]"    logs/live_*.log          # 当日计数汇总
grep -iE "error|warn|2188|2103|2110" logs/nohup_*.log     # 异常
```

### 6.3 每天收盘后核对三件事
1. **信号对不对**：`[信号]` 的区间 lo~hi 与突破价，对照 TradingView/IB 图表上 MNQ 5min K 线
   （9:00–9:29 六根 bar 的高低点、突破那根的收盘价）。
2. **数据实不实时**：`live_*.log` 每行的墙钟时间 vs 行内 bar 时间（如 `[bar] 09:35` 出现在
   09:35:0x）应差几秒内。整体晚 10–15 分钟 = 还在吃延迟数据，订阅没生效。
3. **有没有异常**：nohup 文件里 grep 异常关键字（上表最后一条）。

### 6.4 异常关键字 → 含义
| 关键字 | 含义 |
|--------|------|
| `2188` | 行情订阅未生效/无权限（去 Client Portal 确认，Gateway 重登） |
| `区间为空` | 9:00–9:29 没收到 bar：延迟数据 / useRTH 配置错 / 启动太晚 |
| `2103/2110/2157` | IB 数据农场断连（网络问题），恢复后会自动重连，核对缺口段 bar |
| `[STALE 样本]` | 信号→成交超 2 秒，该笔滑点样本不可信（汇总时自动剔除） |
| `前一日 ATR 不可用` | 日线请求失败，当天不交易（安全侧），重启程序可修 |

## 7. 收盘后停止 + 归档

1. **15:56 之后**执行速查卡 ②。`kill -INT` 触发优雅退出：写 `[停止] 当日统计` 和滑点汇总进日志。
2. 看一眼退出汇总：`tail -5 logs/live_*.log`。
3. **DRY_RUN 阶段**：`live_slippage.csv` 里只有信号+skipped 行，不用动。
   **进入下一阶段前**归档一次：
   ```bash
   mv live_slippage.csv logs/live_slippage_dryrun_0914-0918.csv
   ```
4. `logs/` 永远不删——它是审计底稿（bar 节奏、信号时点、每笔滑点的原始记录）。

## 8. 阶段推进路线：什么时候进入下一阶段

> 原则：每阶段必须**全部判据连续满足**才推进；任何一条不满足，修完重新计数。

| 阶段 | 配置 | 目标 | 毕业判据 |
|------|------|------|----------|
| **1. DRY_RUN**（当前） | `DRY_RUN=True`，paper | 验证**信号时点**（不是滑点） | 连续 5 个交易日：① `[信号]` 与图表核对全对（区间+突破价）② bar 墙钟延迟 ≤ 数秒 ③ ATR/手数/止损价日志合理 ④ 无断线异常 |
| **2. paper 真单** | `DRY_RUN=False`，仍连 paper 4002 | 验证**执行链路**：挂止损、分笔改单、BE 改单、收盘平仓 | ≥5 个交易日：① 每笔入场后恰好 1 张止损单 ② BE 触发后止损价真的变成入场价（TWS/Gateway 挂单页核对）③ 收盘后净持仓归零 ④ 无未处理异常。⚠️ paper 滑点是 IB 模拟的（≈0），只当链路验证，不作真实滑点 |
| **3. MNQ 实盘小仓** | live 账户 4001；`MAX_QTY` 降到 1–2 手 | 采集**真实滑点** | ≥30 笔真实成交，滑点分布中位/75 分位稳定 |
| **4. 校准放大** | 用实测滑点复测回测 | 把 `SLIPPAGE_TICKS` 口径校准后再放大 | 实测滑点代入 GLM_working 边界档位复测无爆仓 → 逐步放大 `MAX_QTY` 至 0.7% 风险算出的满额 |

换阶段只改两处：`DRY_RUN` 开关、（阶段 3 起）`IB_PORT`/`ACCOUNT_ID` + Gateway 登录账户。

## 9. 故障排查

| 症状 | 原因 | 处置 |
|------|------|------|
| 启动即报 2188 | 订阅未生效/未订 | Client Portal 确认 → Gateway 重登 → 重启脚本 |
| 启动即退出 | Gateway 没开/端口被占 | 先起 Gateway；`lsof -i :4002` 查占用 |
| 9:30 后 `区间为空` | 延迟数据 / 收不到盘前 bar | 当天作废；检查订阅与 `use_regular_trading_hours=False` |
| 盘中进程死了 | 各种 | **只要没持仓**：直接重启（区间状态会重建）；**有持仓**：先在 Gateway 手动确认止损单还在（服务器端有效），再重启接管 |
| 电脑睡着了 | 没插电源/没 caffeinate | 同上；`pmset -g` 查睡眠设置 |
| 收盘平仓失败 | 15:55 没收到 bar（断线） | 立刻在 Gateway **手动平仓**，然后排查 |
| 想中途人工干预 | — | 优先在 Gateway 端手动改单/平仓；别在持仓时改代码重启 |
